Rebuilding Google Ads campaign creation in PPCWay

The client wants PPCWay's campaign creation to match the Google Ads "New campaign" flow, step for step, using everything the Google Ads API offers. This page says what that flow is today, what the API can and cannot do, how far PPCWay is from it, and a plan to close the gap.

Researched 12 November 2026 against Google Ads Help, the Google Ads API v25 reference, guides, release notes and deprecation pages. Every claim in the two full research files beside this page carries its source link: the screens, step by step and the API behind each step.

Search

PPCWay builds a small part of a Search campaign today. Full parity is reachable through the API, in one all-or-nothing request, as now.

Performance Max

Fully creatable through the API. It needs images, logos and optional videos, which PPCWay has no way to collect or make yet.

Not creatable

Video, Smart and Local Services campaigns cannot be created through the API at all; Hotel needs Google's allowlist. These stay out of reach whatever we build.

Act on this first: the language setting

Google's API deprecations page and its developer blog (13 August 2026) say that since 30 September 2026, adding a language to a Search campaign fails with ContextError.OPERATION_NOT_PERMITTED_FOR_CONTEXT, in every API version, and that Search ads now match on the language of the ads. PPCWay adds a language on every launch, inside the one all-or-nothing request, so when Google enforces this, every PPCWay launch fails whole.

The "ai pdf tools" campaign launched through PPCWay on 10 November appears to have gone through, so enforcement may not yet reach every account. Google's instruction is still plain: stop sending it. The fix is removing one operation from builder/campaign.py. It is worth doing before anything else on this page.

Performance Max

Google's Performance Max flow has six steps: goal, bidding, settings, one asset group, budget, review. The API creates all of it in one request, in an order Google documents (section 11.2 of the API file). What PPCWay lacks is not the API but the assets.

  • The asset group needs 3 to 15 headlines, 1 to 5 long headlines, 2 to 5 descriptions, a business name, 4 or more landscape and 4 or more square images, 1 to 5 logos, and optional videos. Otto can write the text; the images and logos have to come from the merchant, their website, or an image generator.
  • Signals: audience signals and up to 50 search themes per asset group, both optional.
  • Brand guidelines: on by default, set only at creation; they need a business name and a square logo linked to the campaign.
  • Final URL expansion is on by default, with URL and brand exclusions to rein it in.
  • Bidding is only maximize conversions or maximize conversion value, each with an optional target, and the budget must be daily and not shared.
  • A preview is available for Performance Max through ShareablePreviewService; Search has no preview in the API.

A plan

Now: keep launches working

  • Stop sending the language on Search launches.
  • Show every error Google returns at the check before launch, not only the first.

Phase 1: Search, as complete as Google's

  • The objective and conversion goal step, with a prompt to set up tracking when there is none.
  • Every Search bidding choice with targets and limits, plus customer acquisition after creation.
  • Networks, locations with radius and exclusions, presence or interest, audiences in observation, dates, ad schedule, devices, URL options, IP exclusions.
  • AI Max with its parts and brand lists, as a choice with Google's default shown honestly.
  • All keyword match types, negatives at every level and shared lists.
  • Full responsive search ads: paths, pinning, up to 3 per ad group, Ad Strength read back.
  • Assets: sitelinks, callouts, structured snippets, call, price, promotion, business name and logo, images, location; lead forms once the account is eligible.
  • Budget: daily or total, with Google's recommendations and a forecast.
  • Review that lists every problem with a way to fix it, and policy exemptions where Google allows them.

Phase 2: Performance Max

  • An image and logo step: upload, take from the website, or generate. This is the hard part.
  • The asset group, signals and search themes, brand guidelines, URL and brand exclusions, and the preview.

Phase 3: the rest that the API allows

  • Demand Gen, which reuses Phase 2's images and adds videos.
  • Shopping, for merchants with a Merchant Center feed; App, for merchants with an app.
  • Move the API from v25 to v26 before v25 sunsets in August 2027.

Questions for the client before building

  1. Which campaign types do their customers need? For small businesses after leads, Search and Performance Max cover most of it; Shopping and App only matter to merchants with a feed or an app.
  2. Should PPCWay follow Google's defaults where they cost control, such as AI Max on and search partners on, or keep its tighter defaults and offer Google's as a choice?
  3. Where should images and logos come from for Performance Max and Demand Gen: the merchant's uploads, their website, or generated?
  4. Should the full flow be one long expert screen like Google's, or keep PPCWay's guided steps with an "all settings" view for experts?

Two smaller notes from the research

  • Google's API docs say developer tokens "are deprecated and have been sunset" (9 September 2026) and the header is now ignored. PPCWay still sends it; that does no harm.
  • API v26 shipped on 14 October 2026. PPCWay is on v25, which is supported until August 2027.
